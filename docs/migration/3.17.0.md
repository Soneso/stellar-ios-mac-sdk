# Migrating to 3.17.0

This guide covers the observable changes between 3.16.0 and 3.17.0. If you upgrade from an older version, also review the CHANGELOG between your version and 3.16.0 and the earlier migration guides, newest first: [3.16.0](3.16.0.md), [3.13.0](3.13.0.md), [3.12.0](3.12.0.md), [3.10.0](3.10.0.md). Each note describes one situation: whether you are affected, how it shows, and what to do.

Building a `MemoXDR` text, an `SCValXDR` string, or an `InvokeContractArgsXDR` function name from a `String` compiles unchanged and stores the UTF-8 bytes of the text.

- If you bind the value of `MemoXDR.text` in an `if case` or `switch` pattern and use it as a `String`: the code does not compile. The bound value is `Data`, the bytes of the memo as the XDR holds them. String interpolation of the value compiles and writes the byte count, such as `5 bytes`. In 3.16.0 the case carried a `String`, and a memo whose bytes are not valid UTF-8 failed to decode with `XDRDecoder.Error.invalidUTF8`. Code that reads `Transaction.memo` needs no change. Read the text of a `MemoXDR` with the `textString` property, which gives nil for another arm and for bytes that are not valid UTF-8:

  ```swift
  // 3.16.0
  func memoText(of envelope: TransactionEnvelopeXDR) -> String? {
      if case .text(let text) = envelope.txMemo { return text }
      return nil
  }
  ```

  ```swift
  // 3.17.0
  func memoText(of envelope: TransactionEnvelopeXDR) -> String? {
      return envelope.txMemo.textString
  }
  ```

- If you bind the value of `SCValXDR.string` in an `if case` or `switch` pattern and use it as a `String`: the code does not compile. The bound value is `Data`, the bytes of the string as the XDR holds them. String interpolation of the value compiles and writes the byte count. In 3.16.0 the case carried a `String`, and a value whose bytes are not valid UTF-8 failed to decode with `XDRDecoder.Error.invalidUTF8`. Code that reads the `string` property needs no change. Read the text with that property, which gives nil for another arm and for bytes that are not valid UTF-8:

  ```swift
  // 3.16.0
  func text(of value: SCValXDR) -> String? {
      switch value {
      case .string(let text): return text
      case .symbol(let symbol): return symbol
      default: return nil
      }
  }
  ```

  ```swift
  // 3.17.0
  func text(of value: SCValXDR) -> String? {
      switch value {
      case .string: return value.string
      case .symbol(let symbol): return symbol
      default: return nil
      }
  }
  ```

- If you read `InvokeContractArgsXDR.functionName` as a `String`, for example to check what an authorization entry authorizes: the code does not compile. The property is `Data`, the bytes of the name as the XDR holds them. String interpolation of the property compiles and writes the byte count. In 3.16.0 the property was a `String`, and a name whose bytes are not valid UTF-8 failed to decode with `XDRDecoder.Error.invalidUTF8`. Read the name with the `functionNameString` property, which gives nil for bytes that are not valid UTF-8, and assign a name to the property as `Data(name.utf8)`:

  ```swift
  // 3.16.0
  func isTransfer(_ entry: SorobanAuthorizationEntryXDR) -> Bool {
      guard case .contractFn(let args) = entry.rootInvocation.function else { return false }
      return args.functionName == "transfer"
  }
  ```

  ```swift
  // 3.17.0
  func isTransfer(_ entry: SorobanAuthorizationEntryXDR) -> Bool {
      guard case .contractFn(let args) = entry.rootInvocation.function else { return false }
      return args.functionNameString == "transfer"
  }
  ```

- If you `switch` over a `SorobanContractParserError` without a `default` case: the code does not compile. The error has two new cases, `malformedModule(offset:message:)` and `invalidSectionEntry(section:offset:message:)`, which `SorobanContractParser.parseContractByteCode(byteCode:)` throws for byte code it cannot read. In 3.16.0 the parser could return the entries before an undecodable one without an error. Add both cases or a `default` case.

- If you call `TxRepHelper.formatAsset(_:)`: the code does not compile without `try`. The function throws `TxRepError.invalidValue` for an asset code whose byte count is not the width of its type. In 3.16.0 it did not throw and did not check the byte count of the asset code. Add `try` to the call.
