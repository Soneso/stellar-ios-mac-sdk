# Migrating to 3.16.0

This guide covers the observable changes between 3.15.0 and 3.16.0. If you upgrade from an older version, also review the CHANGELOG between your version and 3.15.0 and the earlier migration guides, newest first: [3.13.0](3.13.0.md), [3.12.0](3.12.0.md), [3.10.0](3.10.0.md). Each note describes one situation: whether you are affected, how it shows, and what to do.

- If you `switch` over `OZContextRuleType` without a `default:` arm: the switch does not compile until it handles `createContractExternalRef(owner:tag:)`, the rule type for contract deployments from an executable reference (CAP-0085). `listContextRules()` returns rules of this type. In 3.15.0 `listContextRules()` and the kit's signing calls threw `SmartAccountValidationException.InvalidInput` for a wallet that held such a rule, with the message `"Invalid input for context_type: Unknown context_type discriminant: CreateContractExternalRef"`. Add the case:

  ```swift
  // 3.15.0
  func label(_ type: OZContextRuleType) -> String {
      switch type {
      case .defaultRule: return "Any call"
      case .callContract(let contractAddress): return "Calls to \(contractAddress)"
      case .createContract: return "Deploys of one WASM hash"
      }
  }
  ```

  ```swift
  // 3.16.0
  func label(_ type: OZContextRuleType) -> String {
      switch type {
      case .defaultRule: return "Any call"
      case .callContract(let contractAddress): return "Calls to \(contractAddress)"
      case .createContract: return "Deploys of one WASM hash"
      case .createContractExternalRef(let owner, let tag): return "Deploys of the code \(owner) stores under \(tag)"
      }
  }
  ```

- If you add a contract (`C...`) address as a Delegated signer, with `OZSignerManager.addDelegated(contextRuleId:address:)` or in the `signers` of `OZContextRuleManager.addContextRule`: the call throws `SmartAccountValidationException.InvalidAddress` before it submits anything. Its message reads `"A delegated signer must be a Stellar account (G-address), got: <address>. Delegating to a contract can let anyone authorize the account."` The wallet's own address throws `SmartAccountValidationException.InvalidInput`. In 3.15.0 the call added the signer. Delegate to a Stellar account (`G...`), or add a passkey or Ed25519 signer. Contract delegates already on a wallet are read as before; remove them (GHSA-jpg9-m7w4-c7wc), or upgrade the wallet and every smart account it delegates to. To list them:

  ```swift
  // 3.16.0
  let rules = try await kit.contextRuleManager.listContextRules()
  for rule in rules {
      for (signer, signerId) in zip(rule.signers, rule.signerIds) {
          if let delegate = signer as? OZDelegatedSigner, delegate.address.isValidContractId() {
              print(rule.id, signerId, delegate.address)
          }
      }
  }
  ```

  Remove a listed signer through an unexpired rule that authorizes without the contract delegate: pass the signers that satisfy that rule as `selectedSigners` to `removeSigner(contextRuleId:signerId:selectedSigners:forceMethod:)`. If every usable rule needs the contract delegate, the kit cannot authorize the removal.

- If you submit `add_signer`, `batch_add_signer` or `add_context_rule` calls on the wallet that you build yourself: `OZTransactionOperations.submit(hostFunction:auth:)` and `OZMultiSignerManager.submitWithMultipleSigners(hostFunction:selectedSigners:)` check the signers these calls add after a successful simulation, before they ask any signer. A Delegated signer that `addDelegated` refuses throws the same errors. A muxed contract address (`W...`) as a Delegated address or an External verifier throws `SmartAccountValidationException.InvalidInput`. On a stellar-accounts 0.8 wallet, a call that adds the wallet itself fails earlier, with `SmartAccountTransactionException.SimulationFailed` reporting 3018 (`SelfDelegatedSigner`). Catch `SmartAccountException` for both. In 3.15.0 the kit signed these calls after a successful simulation without checking the signers they add. Use a Stellar account (`G...`) as the Delegated address and a contract (`C...`) address as the verifier.
